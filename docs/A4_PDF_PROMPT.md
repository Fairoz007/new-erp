# A4 PDF Prompt: one formal A4 format for every printed and downloaded document

Every invoice, note, voucher, payslip, statement and report the app prints or downloads must come out
as the same formal A4 document on the Al Hakim National letterhead. Print and Download PDF must give
the same pages.

# Part B: The A4 standard

## B1. One frame for everything

- **Paper:** A4 210 × 297 mm. Portrait for every document (the letterhead is portrait). See decision 2
  for wide tables.
- **Background:** the fixed letterhead image `src/assets/brand/letterhead-a4.jpg` on every page, loaded
  only when printing or downloading.
- **Safe area:** the `LAYOUT` in `src/lib/invoicePrint.ts`. Nothing is drawn over the printed header
  or the bottom band.
- **Top right, every page:** the document title in capitals (TAX INVOICE, CREDIT NOTE, DEBIT NOTE,
  PURCHASE BILL, PAYMENT RECEIPT, PAYMENT VOUCHER, PAYSLIP, STATEMENT OF ACCOUNT, or the report
  name such as TRIAL BALANCE) and under it the document number, or for reports the period.
- **Bottom corner, every page:** `<number or report name> · Page x of y`.
- **Page 1 block:** seller name, VATIN and CR from Settings; then the facts of that document (party,
  dates, office, reference) or, for reports, the office, the period, the filters used and
  "Generated by <user> on <date time>".
- **Tables:** brand-green header row repeated on every page, rows never split, numbers right-aligned
  to 3 decimals for OMR, totals row once at the end, "No rows" when empty.
- **Closing blocks** where they apply: totals, amount in words in Rials and Baisa, bank details,
  "Prepared by" and "Authorised signature & stamp".
- **Type:** Helvetica (vector text, selectable). The same sizes as `LAYOUT.font`.
- **No screen styling** on paper: no dark cards, gradients, shadows, icons, buttons, menus or badges
  drawn as pills.

## B2. Print = PDF

- One builder per document type produces the pages (jsPDF + jspdf-autotable, as `letterheadPdf.ts`).
- **Download PDF** saves those pages.
- **Print** prints the same pages (for example the generated PDF in a hidden frame, or the shared
  HTML frame from `LetterheadDocument` with the same page plan), so paper and file match. The browser
  print of whole screens (`window.print()` on a page) is no longer used for documents or reports.
- `@page { size: A4; margin: 0 }`; nothing else on the page prints.

## B3. File names

| Kind | Name |
|---|---|
| Invoice, note, bill | `<number>.pdf`, e.g. `447-FT-2026.pdf` (unchanged) |
| Payment receipt / voucher | `<payment number>.pdf` |
| Payslip | `Payslip_<employee code>_<yyyy-mm>.pdf` |
| Statement | `Statement_<client>_<yyyy-mm-dd>.pdf` |
| Report or list | `<Report name>_<office code or All>_<from>_<to>.pdf`, or `<Report name>_<office>_<yyyy-mm-dd>.pdf` when there is no period |

Names keep letters, digits, `-` and `_`; other characters become `_`.

## B4. Documents

| Document | Page 1 block | Body | Closing |
|---|---|---|---|
| Invoice / notes / bill | as today | lines | as today |
| Payment receipt (from a client) / voucher (to a supplier) | received from / paid to, date, method, bank or cash account, reference, office | the invoices it settles (number, date, amount applied) | amount, amount in words, prepared by, received/authorised signature & stamp |
| Payslip | employee name, code, position, office, period, bank account (masked to the last 4 digits) | earnings and deductions side by side | net pay, net pay in words, "This is a computer-generated payslip", employee signature |
| Statement of account | client, address, VAT, period or as-of date | the Bill-wise Details / Pending Bills table | total Dr/Cr, ageing if the data has it |
| Financial statements (Trial balance, P&L, Balance sheet, Cash flow, General ledger) | office, period, basis | the statement as on screen, same figures | totals; "Prepared by / Approved by" |
| Lists and Reports tables | office, period, filters, generated by/on | the table with the columns shown on screen | totals row when the screen has one |

# Part C: Decisions

| # | Decision | Status |
|---|---|---|
| 1 | Every printed and downloaded document uses the full letterhead image, reports and lists included | Requested by the owner |
| 2 | Portrait always. Wide tables first reduce the font (not below 6.5 pt) and wrap text; only above 10 columns use landscape A4 with a header and footer drawn from the logo and the letterhead's footer text (no rotated letterhead image) | Suggested |
| 3 | Print gives the same pages as Download PDF | Requested by the owner |
| 4 | CSV exports stay as they are (data files, not documents) | Suggested |
| 5 | Payslip bank account shows only the last 4 digits | Suggested |
| 6 | The PDF number is the document number; reports show the period instead | Suggested |

# Part D: The prompt (copy everything below this line)

---

## Role and goal

You are working in this repository (React 18, TypeScript, Vite, Tailwind, Supabase). Make every
printed and downloaded document follow one formal A4 format on the company letterhead, as Parts A,
B and C of `docs/A4_PDF_PROMPT.md` describe. Work through the stages in order without stopping to
ask. Record decisions and open points in `docs/A4_PDF_NOTES.md`.

## Rules

- No new features beyond Part B: no new reports, columns, fields or documents. Every figure on paper
  is the figure the screen shows, from the same query.
- No fake data, no hard-coded company details (they come from Settings), no dead buttons.
- Security and office scoping unchanged: a document only contains what the user can already see.
- jsPDF and the letterhead stay out of the initial bundle (`npm run bundle:check`).
- Schema changes only if a document truly needs a stored value; then a new migration and a PGlite test.
- After each stage: `npm run lint`, `npm run test:unit`, `npm run build` and `npm run test:db` pass;
  check the changed outputs by rendering the PDFs to images; one commit ending with the
  Co-Authored-By line.
- Never commit `logs example pdf etc /`, `backups/`, `.env` or `.claude/launch.json`.

## Read first

`src/lib/invoicePrint.ts`, `src/lib/letterheadPdf.ts`, `src/components/common/LetterheadDocument.tsx`,
`src/utils/export.ts`, `src/components/ui/DataTable.tsx`, `src/components/common/ReportPreviewModal.tsx`,
`src/pages/payments/PaymentDetailModal.tsx`, `src/components/common/PrintablePayslipModal.tsx`, the
Print buttons listed in A2, and `docs/UPGRADE_NOTES.md` stage 10.

## Stage 1: One letterhead frame

**1.1** Move the page frame out of `letterheadPdf.ts` into a shared builder
(`src/lib/a4/frame.ts`): letterhead background, corner title and number, footer label, safe area,
page-1 block helper, table defaults (header repeat, no row split, number alignment, totals row),
closing blocks (words, bank, signatures).

**1.2** Rebuild the invoice and statement PDFs on it with no visible change. The existing tests in
`letterheadPdf.test.ts` must still pass unchanged.

**1.3** Add `printPdf(doc)`: prints the generated pages (hidden iframe with the PDF blob), with a
fallback to download when the browser blocks it.

## Stage 2: Lists and reports

**2.1** Replace the body of `exportToPDF` with the frame: title = report name, corner = period,
page-1 block = office, period, filters, generated by/on. Keep its signature so every caller
(`DataTable`, Trial Balance) changes at once. Apply decision 2 for wide tables.

**2.2** Document view (`ReportPreviewModal`): Print uses `printPdf` with the same document.

**2.3** File names as B3.

**2.4** Tests: a 120-row, 5-column list gives the header on every page and page x of y; a 9-column
table stays portrait with readable type; an 11-column table goes landscape; an empty table prints
"No rows"; the file name.

## Stage 3: Financial statements

**3.1** Trial balance, Profit & loss, Balance sheet, Cash flow and General ledger: a builder each
that takes the rows the page already computed. The Print button prints those pages; add Download PDF
next to it where it is missing (decision 3).

**3.2** Reports → Print Report prints the selected report's table through 2.1, not the screen.

**3.3** Tests: totals on paper equal the totals passed in; an account list longer than a page keeps
its header.

## Stage 4: Payment receipt / voucher and payslip

**4.1** Payment receipt (sales) and payment voucher (purchase) as B4, from the payment and its
allocations. Print and Download PDF in `PaymentDetailModal`.

**4.2** Payslip as B4, from the payslip record; remove the invented initials badge. Print and
Download PDF in `PrintablePayslipModal`.

**4.3** Tests: amount in words; the masked bank account; the file names.

## Stage 5: Client statement

**5.1** Reports → Client Statement: Print and Download PDF of the on-screen statement on the frame
(STATEMENT OF ACCOUNT, period, opening balance, movements, closing balance), next to the existing
Pending bills (PDF).

## Stage 6: Check everything

**6.1** For each output in A2 (and A1), produce one file from real or sample data ("Sample…" records,
or a rolled-back transaction so no numbers are used up), render every page to an image, and check:
letterhead exact, nothing over the header or band, title and number/period top right, page x of y
right, header repeated, no split rows, figures equal the screen, file name.

**6.2** Print each from Chrome (and Safari if available) and check the printed pages match the PDF.

**6.3** Record a table of every output with its result in `docs/A4_PDF_NOTES.md`, and anything not
verified.

## Stage 7: Finish

Run `npm run lint`, `npm run test:unit`, `npm run test:db`, `npm run build`, `npm run bundle:check`
and `npm run scan:secrets`. Update README (Printing section) and `AUDIT_REPORT.md`. Commit and push;
check `main` matches `origin/main`. Final report: what changed per output, tests added, page images
